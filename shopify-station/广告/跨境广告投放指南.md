## 一、广告渠道概览

### 1.1 Meta Ads（Facebook + Instagram）

**核心优势：**
- 全球最大定向广告平台
- Pixel 数据最成熟，转化追踪最精准
- 受众定位最丰富（相似受众 + 再营销）
- Instagram 购物功能完善

**广告类型选择：**
| 目标 | 推荐类型 |
|------|---------|
| 爆品测品 | Advantage+ Shopping Campaign (ASC) |
| 品牌建设 | Photo/Video Ad + Carousel |
| 流量测试 | Story Ad + Reels |
| 再营销 | Catalog Sales Ad |

### 1.2 Google Ads

| 类型 | 适用场景 | CPC范围 | 转化周期 |
|------|---------|---------|---------|
| Search | 高意向购买 | $0.5-3 | 短 |
| Shopping | 产品搜索 | $0.3-2 | 短 |
| Performance Max | 全渠道优化 | $1-5 | 中 |
| YouTube | 品牌+转化 | $0.05-0.3 | 长 |

### 1.3 TikTok Ads

| 类型 | CPM | 适合品类 |
|------|-----|---------|
| In-Feed Ads | $3-8 | 颜值/新奇特/趋势品 |
| TopView | $10-20 | 品牌曝光 |
| Collection Ads | $5-10 | 沉浸式购物 |

### 1.4 Pinterest Ads
- 用户：72%女性，收入较高
- 适合：家居、婚纱、服饰、美妆、DIY
- CPC：$0.5-2.5

## 二、受众定位方式

### 受众三层级

```
层级1：Core Audience（兴趣受众）
├── 地域：美国
├── 年龄：25-55
├── 性别：All
└── 兴趣：具体品类关键词

层级2：Custom Audience（自定义受众）
├── 网站访客（Pixel 抓取）
├── 现有客户列表（CRM）
├── 视频/帖子互动用户
└── 再营销受众（30天）

层级3：Lookalike Audience（相似受众）
├── 源受众：top 5% 买家
├── 相似度：1%（精准）或 2-3%（扩量）
└── 叠加：年龄 + 收入分层
```

### 兴趣受众示例（家居品类）
```javascript
{
  "age_min": 25,
  "age_max": 54,
  "geo_targeting": ["United States"],
  "interests": [
    "Home decor",        // 核心兴趣
    "Interior design",   // 扩展兴趣
    "Amazon.com"         // 竞品平台
  ]
}
```

## 三、各阶段出价策略

### Meta Ads 出价阶段

```
冷启动期（Day 1-7）：
├── 预算：$20-50/天
├── 出价：手动 bid cap = 预计 CPC 的 80%
├── 优化目标：AddToCart（低门槛事件）
└── 策略：快速积累数据

测试期（Day 7-14）：
├── 预算：$50-100/天
├── 出价：切换 Cost Cap
├── 优化目标：Purchase
└── 策略：测试 2-3 套受众

放量期（Day 14+）：
├── 预算：$100-500/天
├── 出价：Lowest Cost + 预算翻倍
├── 优化目标：Purchase
└── 策略：复制爆款广告组
```

### Google Ads 竞价策略
```javascript
// Shopping 起步

// 追求 ROAS
```

### TikTok Ads 出价
```
冷启动：$0.1-0.3/点击，优化 Click
测试期：$0.3-0.5/点击，优化 Conversion
放量期：Lowest Cost，优化 Value
```

## 五、像素安装与数据回传

### Meta Pixel 安装（Shopify）

```
1. 创建 Pixel
   Business Manager → Events Manager → 创建像素

2. Shopify 安装
   后台 → Settings → Customer events → 添加自定义像素
```

### 标准事件代码
```javascript
// PageView（自动）

// ViewContent（产品页）
fbq('track', 'ViewContent', {
  content_ids: ['{{ product.id }}'],
  content_type: 'product',
  value: {{ product.price }},
  currency: 'USD'
});

// AddToCart（加购）
fbq('track', 'AddToCart', {
  content_ids: ['{{ product.id }}'],
  content_type: 'product',
  value: {{ product.price }},
  currency: 'USD'
});

// Purchase（完成订单）
fbq('track', 'Purchase', {
  content_ids: [{% for item in cart.items %}'{{ item.product.id }}'{% unless forloop.last %},{% endunless %}{% endfor %}],
  content_type: 'product',
  value: {{ order.total_price | divided_by: 100.0 }},
  currency: 'USD'
});
```

### Facebook Conversions API（服务端回传）

> 关键：Browser Pixel（被 iOS 屏蔽） + Conversions API（补充）双管齐下

```javascript
// Node.js 示例
app.post('/order-confirmed', async (req, res) => {
  const { order, customer } = req.body;
  
  const eventData = {
    event_name: 'Purchase',
    event_time: Math.floor(Date.now() / 1000),
    action_source: 'website',
    user_data: {
      em: hash(customer.email),   // SHA256
      ph: hash(customer.phone),   // SHA256
    },
    custom_data: {
      content_ids: order.items.map(i => i.product_id),
      content_type: 'product',
      value: order.total_price / 100,
      currency: 'USD',
      order_id: order.id
    }
  };
  
  await fbPixel.events.send(eventData);
  res.json({ success: true });
});
```

## 六、风险控制

### 账户被封常见原因

```
1. 支付问题
   ├── 信用卡被拒
   ├── 支付方式关联过多账户
   └── 账户信息不一致

2. 违规内容
   ├── 虚假广告/夸大功效
   ├── 侵权内容（品牌/音乐/图片）
   └── 误导性图片

3. 账户关联
   ├── IP/设备指纹关联
   ├── BM 共享问题
   └── 管理员个人账户被封
```

### 预防措施

```
1. 账户架构隔离
   ├── 每品类单独 BM
   └── 避免 BM 间共享资产

2. 支付安全
   ├── 稳定的美国信用卡
   ├── 预付充值（Meta Credit）
   └── 避免频繁更换支付方式

3. 内容合规
   ├── 避免绝对化用词（#1, best, never）
   ├── 使用正版素材
   └── 明确标注"Ad"

4. BM 架构
   ├── 主 BM：品牌主页 + 核心像素
   ├── 品类 BM：独立广告账户 + 隔离像素
   └── 测试 BM：新产品隔离
```

### 解封申诉流程

```
步骤1：诊断封号原因
   Business Manager → 安全中心 → 查看违规通知

步骤2：准备申诉材料
   ├── 网站 URL + 产品资质
   ├── 广告截图 + 投放历史
   └── 整改说明

步骤3：提交申诉
   Meta Business Help Center → Account → Disabled Account
   等待 3-7 个工作日

步骤4：备用方案
   ├── 准备 2-3 个备用 BM
   ├── 不同 IP/设备登录
   └── 避免再次关联
```

## 七、新品冷启动流程

### Day 1-3：像素验证
```
目标：确认数据追踪正常
预算：$20/天（全投 ViewContent）

验证清单：
□ Meta Pixel Helper 显示 PageView
□ 加购事件正常触发
□ 产品页事件包含正确 SKU
□ 时间戳合理

异常处理：
✗ Pixel 不触发 → 检查代码安装
✗ 事件缺失 → 检查事件配置
✗ SKU 错误 → 检查数据层
```

### Day 4-7：受众测试（$30-40/天）

```
组1：Interest 受众
├── 自动竞价
├── Interest：核心品类词
└── 预算：$15/天

组2：相似受众 1%
├── 种子：历史买家 top 1%
└── 预算：$15/天

组3：再营销受众
├── 网站访客 30 天
└── 预算：$10/天

判断：连续 2 天无转化 → 暂停该组
```

### Day 8-14：素材测试（$40-50/天）

```
4 套素材测试：
├── A：痛点+解决方案视频
├── B：产品展示+使用场景
├── C：对比图（Before/After）
└── D：UGC 风格口播

每套：$10-12/天

判断：3 天内 CPM > $15 或 CTR < 0.5% → 立即更换
```

### 爆品判断标准

```
✓ 信号1：3天内自然出单
  → 爆品概率 > 70%

✓ 信号2：加购率 > 5%
  → 产品吸引力强，值得加预算

✓ 信号3：CPM 持续下降
  → 素材通过审核，进入放量期

✓ 信号4：订单自然搜索占比 > 20%
  → 有真实市场需求
```

### 爆品生命周期

```
启动期（Day 1-7）：测试
├── 预算：$20-50/天
└── 决策：保留/放弃

验证期（Day 8-14）：放量测试
├── 预算：$100-200/天
└── 决策：加仓/优化/放弃

放量期（Day 15-30）：规模化
├── 预算：$500+/天
└── 策略：复制爆款广告组

衰退期（Day 30+）：清仓/转型
├── 特征：CTR 下降，CPM 上升
└── 决策：收缩预算，测试新品
```

## 八、典型亏损案例

### 案例1：爆品测死
```
产品：折叠水壶，$29.99
预算：$100/天，跑了 30 天
总花费：$3000
结果：亏损

原因：
1. Amazon 同类竞争太激烈
2. 物流时效 7-15 天，退货率高
3. 功能性产品复购率极低

教训：
✓ 功能性产品慎选：复购率低
✓ 提前调研 Amazon 竞争度
✓ 设置止损线：7 天 CPM > $30 立即暂停
```

### 案例2：像素数据污染
```
诡异现象：
- 加购率 10%，但 Purchase 只有 0.3%
- 大量用户加购后消失

原因：网站有多个 Pixel（员工测试+代理+主 Pixel）

教训：
✓ 一个网站只用一个主 Pixel
✓ 禁止硬编码多个 Pixel
✓ 用 GTM 统一管理所有标签
✓ 定期用 Pixel Helper 检查
```

### 案例3：账户关联封号
```
失败：
3 个广告账户，共享 BM
主账户被封 → 连带 3 个子账户全部被封

原因：
1. 3 个账户用同一张信用卡
2. 管理员账户是同一个人
3. IP 段完全相同

教训：
✓ 每账户独立 BM
✓ 独立支付方式
✓ 不同 IP 登录（指纹浏览器）
✓ 高风险品类提前准备备用账户
```

### 案例4：素材侵权
```
结果：
Day 3：广告被拒
Day 4：收到版权投诉
Day 5：账户被封

教训：
✓ 永远不要用未授权 IP
✓ 不要用热门音乐
✓ 不要用明星照片
✓ 自己设计或购买正版素材
```

## 十、投放检查清单

### 上线前必查
```
□ 像素验证正常（Pixel Helper 测试）
□ 落地页加载速度 < 3 秒
□ 移动端体验正常
□ 支付流程顺畅（测试下单）
□ 客服联系方式可见
□ 退换政策明确
□ 产品评价至少 10+
□ 无侵权内容
□ 价格与 Amazon 相比有竞争力
□ 物流时效说明清楚
```

### 运营中必查
```
□ 每日监控 CTR 和 CPM
□ 每周分析 CVR 变化
□ 定期清理低效受众
□ 检查 Pixel 数据一致性
□ 监控账户健康度
□ 保持广告账户余额充足
□ 定期备份受众数据
□ 记录投放数据复盘
```

### 风险预防必查
```
□ 准备 2 个以上备用 BM
□ 独立支付方式
□ 不同 IP 登录（指纹浏览器）
□ 定期更新密码
□ 启用双因素认证
□ 记录所有账户信息
```
